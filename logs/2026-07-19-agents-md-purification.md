# 2026-07-19 — AGENTS.md 职责净化 + RULES.md 定位校正

## 为什么

调查发现 AGENTS.md 混入了事件性内容（§6.2 实测数据含具体 PASS 数字与日期），违反"只放规则、不放事件"的职责边界。同时存在模糊措辞（"应/可以/避免"）削弱约束力。通过 OpenCode 二进制 strings 验证确认：AGENTS.md 被 SDK 自动注入 system prompt（每次 LLM 请求生效），RULES.md 被 SDK 零识别（依赖 AGENTS.md §5 强制读取），两者加载机制根本不同，需明确分工。

## 改了什么

- **§6.2 实测数据迁出**：`2026-07-18 实测 92/92 PASS、92/93 PASS、port 4001、1/1 PASS` 迁到 `logs/2026-07-18-test-baseline.md`。AGENTS.md §6.2 只保留规则句，并收紧为强约束措辞（"必须/禁止"）。
- **§1.3 去日期**：标题"（2026-07-18 校准）"改为"（以 work-one 实测为准）"——日期属事件，规则不带日期。
- **§最后更新**：2026-07-18 → 2026-07-19。
- **强约束措辞收紧（11 处）**：
  - §7.1：优先→必须优先、可以→允许、应→必须、不要→禁止
  - §7.3：优先→必须（3 处）
  - §7.4：避免→禁止、补必须（3 处）
  - §11.2：应→必须
- **RULES.md 定位校正**：顶部加定位声明（含加载机制说明：SDK 零识别，依赖 AGENTS.md §5 强制读取）；第8条加"完整代码风格详见 AGENTS.md §7"；第10条加"完整验证层级详见 AGENTS.md §4.3"。

## 决策

- **不下沉 §7 到 code-style skill**：pre-flight-enforcement 非全局强制，下沉后 skill 会成为死代码；AGENTS.md 是 session 必读，规则写在里面直接生效。
- **不下沉 §8 到 RULES.md**：§8 是项目特定强约束（不得裸跑 serve 等），且 RULES.md 不被 SDK 自动加载，放进去会失效。
- **不迁移 RULES.md 内容到 AGENTS.md**：会制造重复双源。改为交叉引用注脚，明确 AGENTS.md 为单一权威源。
- **保留 §5 第1条对 RULES.md 的强制读取要求**：这是 RULES.md 实际生效的唯一机制，不动。

## 更新了什么文档

- `AGENTS.md`：§6.2 净化、§1.3 去日期、§最后更新改日期、§7/§11.2 强约束措辞收紧
- `RULES.md`：顶部定位声明、第8条与第10条交叉引用注脚
- `logs/2026-07-18-test-baseline.md`：新建，迁出的实测数据
- `logs/2026-07-19-agents-md-purification.md`：本日志
