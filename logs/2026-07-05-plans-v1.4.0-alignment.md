# 2026-07-05 Plans 对齐 Blueprint v1.4.0

## 变更

根据 `blueprints/blueprint-opencode-framework-simplification-roadmap.md` v1.4.0 的调查结论和架构转向，更新 `plans/` 下全部 7 个计划文档。

### 核心变更

1. **Orchestrator 唯一自定义 agent**：从"10 个自定义 Agent + alias manifest"转向"Orchestrator 作为唯一自定义 agent，其他角色由原生 agent (plan/build/general/explore/scout) + Skill 承载"。

2. **alias_of 已确认无效**：Blueprint v1.4.0 源码调查确认 OpenCode 官方 JSON Schema 和 runtime 均不支持 `alias_of`/`extends`/`inherits`。`native` 字段只写不读。config hook 返回值被 `Effect.ignore` 丢弃。所有计划文档中"验证 alias_of 是否被 runtime 使用"的任务标记为已确认无效。

3. **行为型 Enforcement**：从"身份绑定型"（agent X 允许用 tool Y 吗）转为"行为型"（tool Y 在 path Z 上安全吗）。识别 6 个待删除的 per-agent 检查层：readDispatchAllowedTools、isWriteAllowed、getAgentPermission、config-read-attest per-agent、tool 白名单 per-agent、permission reader per-agent。

4. **角色行为内聚到 Skill**："你是谁、做什么"从自定义 agent prompt 内聚到 Skill bundle，通过权限和触发条件组合给不同原生 agent。

## 追加变更：权限矩阵、Break-Glass 协议与 QoderWork ACP 接口契约

### 1. 原生 Agent Permission 矩阵（03-phase2）

确认 OpenCode 支持在 `opencode.json` 中覆写原生 agent（build/general/explore/plan）的 permission，merge 语义。在 03-phase2 中新增完整的权限矩阵：

- **OpenCode 原生工具**：`edit`/`bash` 对 build/general 设为 `deny`（封死原生写工具），explore/plan 保持原生 deny。`read`/`glob`/`grep` 全 allow。`task` 全 deny（仅 Orchestrator 可派遣子 agent）。`skill` 全 allow（关键——加载 Skill 注入角色行为）。
- **safe_* 自定义工具**：`safe_edit`/`safe_shell`/`safe_test` 按 agent 分级 allow/deny，走独立 plugin tool 路径，不受 edit/bash deny 影响。
- **MCP 工具**：`codegraph_*` 对可写 agent allow，`context7` 按需 allow。
- **QoderWork 桥接**：`question`/`acp_notify` 全 allow。
- **旧框架工具退役**：`compliance_gate_*`、`checklist_*`、`config_read_attest`、`tool_enforcement_*`、`scope_validate_*`、`read_dispatch_*` 全部标记为待删除。

### 2. Super-Admin Break-Glass 协议（03-phase2）

设计 break-glass 为 `safe_edit`/`safe_shell` 的 `breakGlass: boolean.optional()` 参数，不新增自定义 agent。在 03-phase2 中新增：

- `breakGlass=true` 跳过路径限制检查，记录审计日志到 `break-glass.jsonl`。
- 新增 `break-glass-protocol` Skill（第 18 个），定义触发条件、执行方式和安全约束。
- 调用流程：Orchestrator 识别需要 break-glass → 加载 Skill → 派遣 build → `safe_edit(breakGlass=true)` → 审计日志。

### 3. QoderWork ACP 接口契约（02-phase1 T1.11）

新增 T1.11，定义框架侧与 QoderWork 侧的接口契约：

- **信号源定义**：框架 Hook 写入 `.task_temp/_logs/` 下 4 个 JSONL 文件（`audit.jsonl`、`quality.jsonl`、`guidance.jsonl`、`break-glass.jsonl`）。
- **检测规则 R1-R7**：`repeated_failure`（3 次/30min）、`skipped_brainstorming`、`skipped_skill`、`todo_stall`（10min）、`no_verification`、`break_glass_usage`、`quality_degradation`（组合触发）。
- **介入通道**：`qoder_send_message` / `qoder_delegate_to_im`，可执行建议而非 hard block。
- **跨会话观察**：通过 memory 系统记录质量趋势，识别跨 session 模式。
- **验收标准**：新增 QoderWork ACP 接口契约 smoke test 验收项。

### 4. 02-phase1 general 的 todowrite 权限确认

确认权限矩阵中 general 的 `todowrite` 已为 `allow`，与 TodoWrite 作为 LLM 外置工作记忆的定位一致。
