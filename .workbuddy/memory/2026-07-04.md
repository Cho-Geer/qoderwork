## Question 混合 Enforcement 优化方案设计

**任务**: 基于多轮讨论，设计 question 工具 + 计数器 + system.transform 的混合 enforcement 方案

**关键发现**:
- 框架 tool-tracker.ts:602 的 requestGuidance() 函数注释明确写着 "agent called 'question' tool"
- 框架原始设计意图就是用 question 工具作为汇报通道，acp_notify 是后加的替代路径

- QoderWork 直写 DB 下发指导（零 MCP 依赖）
- question 返回后 after-hook 调用 clearAwaitingGuidance() 自动重置
- 覆盖 5 个互动场景：有疑问、用户决策、累积失败、循环阻断、主动推送

## doc-code-sync Skill 创建

**任务**: 创建文档代码同步 skill，自动维护 documents/INDEX.md 索引文件

**交付物**: `.workbuddy/skills/doc-code-sync/SKILL.md`（agent_created: true，项目级）

**七步工作流**:
1. 收集文档元数据（文件名/行数/修改时间，排除 INDEX.md）
2. 读取当前 INDEX.md（解析表格+场景推荐+更新日志）
3. 对比检测变更（新文件 / 比 INDEX.md 更新 / 行数漂移 >±2）
4. 读取变更文档并生成中文摘要（≤50字，主题+概述+目标读者）
5. 重写 INDEX.md（保留格式：表头说明+表格+按场景推荐阅读+历史更新压缩）
6. 写入文件（Write 到 Windows temp → cp 到 WSL 路径，避免 UNC 路径 Write 被拒）
7. 报告变更摘要

**关键设计**:
- 双访问模式：WSL bash（首选）+ UNC 路径 fallback（WSL 被安全策略禁用时）
- 零变更不写入（避免 git diff 噪音）
- 摘要描述文档内容而非外部事实（文档有错是文档修复，非索引修复）
- 架构数量以 MEMORY.md 权威值为准

**验证**: 执行 skill 工作流扫描 10 个文档，INDEX.md（mtime 15:46:54）比所有文档都新，行数漂移仅 1 行（837→838，在 ±2 容差内），判定零变更，不写入
