# 更正/补充：Reasonix plugin 与 hook 具体用法（二次调查，官方 docs+source）

**plugin 本质**: Reasonix 的 plugin = MCP 式外部工具提供方，不是 opencode 那种 TS 生命周期拦截器
- 配置: config.toml 的 [[plugins]] 表(name + command [+ args])，或项目 .mcp.json，或 --mcp flag
- 线协议: 可执行程序经 stdin/stdout 的 newline-delimited JSON-RPC 2.0（即 MCP stdio 约定）；远程工具适配为 Tool 接口
- 参考实现: cmd/reasonix-plugin-example；main-v2 GUIDE 用 [[plugins]]，旧文 mcpServers 对象疑为 legacy

**hook 本质**: shell 命令，生命周期事件触发，配在 settings.json（非 config.toml）
- 位置: 项目 /.reasonix/settings.json(需 /hooks trust，信任态存 ~/.reasonix/trust.json) + 全局 ~/.reasonix/settings.json(始终信任)
- 事件: 门控 PreToolUse(exit2阻止/0放行,默认5s) / UserPromptSubmit(exit2中止整轮)；通知 PostToolUse(默认30s,非零仅警告) / Stop / SessionStart / SessionEnd / PreCompact(stdout 并入压缩摘要)
- entry 字段: match(锚定正则过滤工具) / command / description / timeout(ms)；事件 JSON 经 stdin 传入
- 高级: PreToolUse 可 stdout 返回 hookSpecificOutput:{permissionDecision,updatedInput,...} 改写工具输入；PostToolUse 可 updatedMCPToolOutput
- 项目 hook 先于全局；同作用域按数组序；门控事件遇首个阻塞 hook 即停

**对迁移的含义**: opencode before/after TS plugin-handler 不能直搬——工具拦截/改写语义在 Reasonix 对应 Hooks(PreToolUse/PostToolUse shell 脚本读 stdin JSON)，“外部工具”语义对应 [[plugins]]/MCP。.reasonix/setting.json(缺s且位置错)非有效文件，应为 /.reasonix/settings.json

## L1-001 live E2E rerun + skill-summary root cause (2026-07-11)
