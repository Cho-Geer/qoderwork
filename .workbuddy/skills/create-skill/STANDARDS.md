# create-skill standards

## Quality bar

- Scope is explicit and narrow enough to trigger reliably
- Description states what the skill does, when to use it, and when not to use it
- Workflow steps are ordered and executable
- Verification steps, when present, require `Verified-by:` evidence
- Broken local links are not allowed

## Avoid

- Empty or generic descriptions
- Hidden assumptions about tools or directories
- Mixing design guidance with runtime proof
- Referring to files that do not exist in the skill package
