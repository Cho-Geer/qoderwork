## 3. §6 Step 4c Deviation 合法性裁决

**M3 deviation**: plan §6 Step 4c canonical pattern puts `type SubmitResult, type ApproveResult` inside a value destructuring `const { ..., type X } = await (async () => {...})()`. M3 instead used `const mcpDeliv = await (async () => {...})()` + `const { submit..., approve... } = mcpDeliv` + `type SubmitResult = (typeof mcpDeliv)["SubmitResult"]`.

### 3.1 TS1005 root-cause independently reproduced

Probe file `/tmp/ts1005-test/probe.ts`:
```ts
const mod = await (async () => ({ a: 1, T: 2 as const }))();
const { a, type T } = mod;
```
`tsc --noEmit --pretty false --strict probe.ts` → `probe.ts(2,17): error TS1005: ',' expected.`

**Confirmed**: `type` modifier inside a value destructuring pattern is a TS syntax error (TS1005). The plan §6 canonical pattern, applied literally to L8-L11 of `regress-parent-child.ts` (which mixes value imports `submitDeliverablesWithCrossCheck, approveDeliverablesWithAudit` with `type SubmitResult, type ApproveResult`), would not compile. The deviation is **necessary**, not cosmetic.

### 3.2 Type-alias semantic equivalence

- Original (verified via `git show HEAD~5:scripts/regress-parent-child.ts`): the L8-L11 import block imports both values and types from `/home/zhaoge/.../mcp-deliverables`.
- M3's replacement: `const mcpDeliv = await import(...)` returns the **module namespace object**; `(typeof mcpDeliv)["SubmitResult"]` extracts the type of the named export. This is the canonical TypeScript pattern for "import a module dynamically, then derive types from its namespace" — semantically equivalent to `import type { SubmitResult } from "..."`.
- **Downstream usage verified** (grep `SubmitResult|ApproveResult` in `regress-parent-child.ts`):
  - L22/L23: `type SubmitResult = (typeof mcpDeliv)["SubmitResult"]; type ApproveResult = ...`
  - L87: `let r: SubmitResult | ApproveResult = submitDeliverablesWithCrossCheck(...)`
  - L148/L154: `(r as ApproveResult).approved_by`
- All type references resolve. `bun run typecheck` EXIT=0 (§2 #1) confirms the type alias is structurally valid.

### 3.3 Boundary compliance

- **Same file**: yes — still `scripts/regress-parent-child.ts`.
- **Same relativePath**: yes — `.opencode/service/gate/mcp-deliverables.ts` (plan §6 Step 4c spec preserved).
- **Same logical import count**: yes — still 1 IIFE for the L8-L11 logical import.
- **No out-of-scope behavior**: yes — no other file touched, no extra side effect.
- **M3主动报告未遮掩**: yes — M3 §2 row "Step 4c" explicitly documents the deviation + root cause (TS1005) + alternative chosen. M3 §6 "cross-section propagation" reiterates. Not silent.

## 7. 加项检查 — GLM-5.2 独立发现的漏点 / 风险

### 7.1 DEFECT (medium) — MSYS2/Git-Bash path-mangling defeats `grep -c "/home/zhaoge ..."` patterns

**Discovery**: While independently verifying the §7 step 2 result, I ran a parallel bash check:

```bash
grep -c '/home/zhaoge' scripts/_d3_live.ts
```

This returned **0** on all 3 files known to contain residual `/home/zhaoge` strings. Cross-checks confirmed:
- `grep -c "zhaoge"` (no leading slash) → 5 in `_d3_live.ts` ✅
- `grep -c "home/zhaoge"` (no leading slash) → 5 ✅
- `grep -c "/home/"` (leading slash) → 0 ❌
- `grep -c "/zhaoge"` → 0 ❌

Python byte-level scan (the authoritative source per plan §7 step 2) confirms `_d3_live.ts` actually contains 5 occurrences of `/home/zhaoge`, `diag-handover-path.ts` 1, `regress-parent-child.ts` 1 — total 7, matching plan §7 step 2 output.

**Root cause**: MSYS2/Git-Bash POSIX path translation rewrites argv elements starting with `/` to Windows paths before they reach the grep binary. The grep never sees the intended pattern.

**Impact on M3 report**: M3's evidence chain includes some `grep -c "/home/..."`-style "Verified-by" lines. If any of those were the **sole** evidence for `import_hits=0`, the conclusion would be untrustworthy. In this case it is **not** the sole evidence — plan §7 step 2's Python script is the authoritative gate and is grep-independent. Therefore M3's **conclusion is correct**, but **the evidence-chain rigor is below audit-separation best practice**.

**Recommendation for M3 (or main session)**: in future iterations, when verifying path-string patterns from Git-Bash on Windows, either (a) use `grep -c -F -- "/home/zhaoge"` with `--` to terminate options, or (b) double every grep "Verified-by" with a Python one-liner, or (c) use `MSYS_NO_PATHCONV=1 grep ...`. This is a documentation/process nit, not a code defect.

M3 used `import { pathToFileURL } from "node:url"` (double quotes) in `_d3_live.ts` and `test-hybrid-enforcement.ts`, while the other 4 files use single quotes per plan §6 canonical snippet. This is **cosmetic and TS-legal** (both quote styles are valid ESM), and M3 §2 "Declarations-per-file" footnote acknowledges it. Not a defect; flagged only for completeness.
