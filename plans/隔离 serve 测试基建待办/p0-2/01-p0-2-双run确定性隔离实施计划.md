## 2. 问题、根因与验收矩阵

### 2.1 当前缺口

当前实现已经具备单 run 原语，但没有证明两个真实 run 同时存活时仍满足隔离：

- `createRunContext()` 为每个 run 生成唯一 worktree、framework DB、OpenCode DB、日志和事件路径。
- `startRunProcesses()` 会释放 reservation，并以 health、serve identity、SSE identity、SSE ready 四项 gate 裁决 `READY`。
- `stopRunProcesses()` 在 PID 与 `QODERWORK_TEST_RUN_ID` 不匹配时拒绝终止。
- P0-1B 只证明单 run 生命周期，不能证明 A/B 并存、SSE 不串流、DB 不串写或 stop A 不伤害 B/外部 PID。

根因不是缺少单个底层函数，而是缺少三项系统级闭环：

1. 一个固定阶段的双 run coordinator。
2. 一个只读、跨 A/B/主 DB 的确定性 oracle。
3. 一个真实同时启动两套 serve/SSE 的 runtime-smoke gate。

### 2.2 P0-2 唯一验收矩阵

| ID | 必须证明 | 确定性 oracle |
|---|---|---|
| P02-ISO-01 | A/B run ID 与全部可写路径不同 | manifest 字段逐项比较，realpath 均位于各自 rootDir |
| P02-ISO-02 | A/B reservation 同时成立 | 两个 reserver PID 不同且存活；两个端口均处于监听状态 |
| P02-ISO-03 | 真实 serve 接管各自 reservation | 原 reserver PID 已退出、manifest 字段为 null、四项 READY gate 全真 |
| P02-ISO-04 | A 的 session/grant 不进入 B | A 的 SDK/framework DB 有记录；B 的两 DB 无 A session/grant |
| P02-ISO-05 | A 的 session/grant 不进入主 framework DB | 以 readonly DB 连接查询 A root/child/grant，结果全为空 |
| P02-ISO-06 | A 的 SSE 只归属 A | A events 有 A root/child `session.created`；B events 无这两个 session ID |
| P02-ISO-07 | stop A 不影响 B | A serve/SSE 已退出；B health、PID identity、SSE ready 继续为真 |
| P02-ISO-08 | stop A 不影响外部 PID | 独立 sentinel 在 stop A 前后 PID identity 和存活检查均为真 |
| P02-ISO-09 | cleanup 相互独立 | cleanup A 时 B 仍 READY；最后 A/B 都 CLEANED、worktree 删除、evidence 保留 |
| P02-ISO-10 | 失败不伪造 PASS | 首个失败后不执行后续业务阶段；仅受控 stop；不清理失败 run，不同 run 不重试 |
| P02-ISO-11 | 强制 overlay/apply 失败不留资源 | 复用真实临时 repo 故障注入；无残留 worktree/进程/reservation，manifest 为 BLOCKED |

## 3. 方案裁决

### 3.1 已比较方案

| 方案 | 结论 | 原因 |
|---|---|---|
| 仅在 `p02-runtime.test.ts` 手写 A/B 生命周期 | 拒绝 | 无正式 CLI 入口、阶段证据和失败收敛；弱模型容易重复启动或漏停一个 run |
| 给 `runP01b()` 增加双 run mode | 拒绝 | 污染已经闭合的 P0-1B 八阶段契约，使单 run 与双 run 状态机耦合 |
| 新增 `p02-orchestrator.ts` + `verify-p02.ts` + `p0-2` CLI | **采用** | 单一职责、可注入 component test、可形成单命令 runtime 证据，且不修改 P0-1B 契约 |

本计划没有待选择项。执行 Agent 必须采用第三条，不得改为 shell 串联命令或手工 `curl`/SQL。

### 3.2 固定运行拓扑

```text
reviewer ports A/B
        │
        ▼
p0-2 CLI adapter
        │
        ▼
p02-orchestrator
  ├── run A: worktree + framework DB + SDK DB + serve + SSE + evidence
  ├── run B: worktree + framework DB + SDK DB + serve + SSE + evidence
  ├── external sentinel PID
  └── verify-p02 readonly oracle
        ├── compare A/B manifests and files
        ├── query A/B isolated DBs readonly
        └── query main framework DB readonly
```

## 5. 固定类型与阶段契约

### 5.1 `P02_STAGES`

顺序必须逐字固定为：

```ts
export const P02_STAGES = [
  "create-a",
  "create-b",
  "verify-reservations",
  "start-sentinel",
  "start-a",
  "start-b",
  "verify-coexistence",
  "bootstrap-a",
  "verify-attribution",
  "stop-a",
  "verify-after-stop-a",
  "cleanup-a",
  "stop-b",
  "cleanup-b",
  "stop-sentinel",
  "verify-cleanup",
] as const;
```

不得并行执行两个 `git worktree add`；`create-a` 与 `create-b` 串行，但从 `create-b` 完成到 `stop-a` 开始期间，两个 run 必须同时存在；从 `start-b` 完成到 `stop-a` 开始期间，两套真实 serve/SSE 必须同时为 READY。

### 5.2 输入与输出

`P02Input` 固定字段：

- `primaryWorktree: string`
- `commit: string`
- `portA: number`
- `portB: number`
- `testId: string`
- `mainFrameworkDbPath: string`

输入拒绝条件：路径非绝对、文件/目录不存在、端口越界、两个端口相同、`testId` 为空。不得接收 `--retry`、`--skip-*`、`--run-dir-a/b`、shell command 或 H2 参数。

成功 JSON 固定包含：

- `ok: true`
- `status: "PASS"`
- `runA`、`runB`：各自 `runId/runDir/manifest/cleanupReport/artifactsDir`
- `checks.reservations/coexistence/attribution/afterStopA/cleanup`
- `evidencePaths.stageResults`

失败 JSON 固定包含：

- `ok: false`
- `runA/runB` 的已知 runDir，未知则为 `null`
- `firstFailure.stage/error`
- `evidencePaths.stageResults`
- `controlledStops`：对 A、B、sentinel 的尝试与结果

### 5.3 失败收敛

任一阶段失败后固定执行以下收敛，不得改变顺序：

1. 停止 sentinel，但只在其 marker/env identity 与 PID 一致时执行。
2. 若 B manifest 存在且 reservation/PID 属于 B，最多调用一次 `stopRunProcesses(B)`。
3. 若 A manifest 存在且 reservation/PID 属于 A，最多调用一次 `stopRunProcesses(A)`。
4. 不调用 `cleanupRun(A/B)`；保留 worktree、DB、events、logs、manifest 和 stage results。
5. 不修改失败 manifest 来伪造 `STOPPED/CLEANED`；不在同一 run 重试任何阶段。

## 7. 12 子系统合规审计

| 子系统 | 固定约束 |
|---|---|
| MVC Architecture | CLI 只适配；编排在 `p02-orchestrator`；oracle 在独立模块 |
| DB-only & DB-canonical | session/grant 以 DB 为真相源；manifest 只保存运行元数据 |

| Concurrency Safe | A/B 独立端口、worktree、双 DB、PID、日志、事件；同时 READY 实测 |
| Hardened Enforcement | serve 环境继续固定 hard gate；P0-2 不关闭或绕过它 |
| Framework Harness | 使用真实 opencode serve、真实 SSE、真实 bootstrap；不 mock runtime |
| Central State Management | 每个 run 仍由自身 manifest 控制；协调器只引用，不复制状态 |
| Multi-Agent | A root/child/grant 正向链路与 B/主 DB 负向隔离同时裁决 |
| Log Central Management | A/B 日志与 events 各归其 run；正式 evidence 不只存 `/tmp` |
| DB-canonical Management | 所有 oracle readonly；禁止手写 session/grant 数据 |
| Templatization & Parameterization | 两端口、commit、主 DB 路径显式输入；无固定端口 |
| TypeScript + Bun Runtime | TypeScript/Bun/Node argv spawn；无 shell 拼接、无新增依赖 |

## 8. 风险与回滚

| 风险 | 检测 | 处理 |
|---|---|---|
| 两端口相同或已占用 | input gate + reservation | 创建 run 前 fail-closed |
| reservation 释放后 serve 未接管 | 原 PID/manifest/READY 四 gate | 标记 firstFailure，受控 stop，保留现场 |
| A 事件进入 B | B events/session_map 负向 oracle | FAIL，不清理失败 run |
| A 记录进入主 DB | 主 DB readonly query | FAIL，保留 A/B/主 DB 查询证据 |
| stop A 误杀 B/sentinel | B health/identity + sentinel marker | FAIL；不继续 cleanup |
| cleanup A 影响 B | cleanup A 后再次检查 B | FAIL；保留 B run |
| `/tmp` 被清空导致证据丢失 | 检查 state root | 正式 run 强制使用持久 XDG state |

回滚只限本计划文件表 #1–#10 的代码/测试/CLI变更，以及尚未宣告 PASS 的 skill 草稿。不得使用 `git reset --hard`，不得覆盖当前工作树其他变更。失败日志、run dirs、DB、events 与 firstFailure 必须保留。
